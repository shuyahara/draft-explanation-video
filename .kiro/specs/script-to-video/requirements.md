# Requirements: script-to-video（台本→機械音声解説動画 生成ツール）

## Introduction

台本ドキュメント（Markdown ＋ シーン YAML）から、機械音声ナレーション付きの解説動画
（MP4）を自前パイプラインで生成する自分専用ツール。HeyGen への手動貼り付け運用を置き換え、
「執筆時に Claude が素材候補とライセンスを確定 → 実行時にツールが決定的に処理 →
人がギャラリーで承認」という三段のワークフローで、手動作業を承認操作のみに減らすことを
目的とする。

## Requirement 1: シーン YAML（レンダリング指示書）の読み込み

**User Story:** As a 動画制作者, I want 台本執筆時に確定させたレンダリング指示書をツールに読み込ませたい, so that 実行時の推定処理（LLM 呼び出し）なしに決定的に動画を生成できる.

### Acceptance Criteria

1. シーン YAML が与えられたとき、システムはシーンごとの「ナレーション本文・テロップ・素材検索クエリ（英語）・候補素材 URL とライセンス情報・生成プロンプト・読み修正・ポーズ秒数・出典情報」を読み取ること
2. YAML に必須項目の欠落や形式エラーがある場合、システムはレンダリングを開始する前に、どのシーンの何が不正かを特定して報告すること
3. システムは実行時に LLM を呼び出さないこと（検索語・読み・プロンプトはすべて YAML から取得する）

## Requirement 2: 音声合成（ナレーション）

**User Story:** As a 動画制作者, I want 台本のナレーションをローカル TTS で音声化したい, so that ランニングコストなしで全シーンの音声を自動生成できる.

### Acceptance Criteria

1. シーンごとのナレーション本文が与えられたとき、システムはローカルの VOICEVOX 系エンジンでシーン別の音声ファイル（WAV）を生成すること
2. YAML に読み修正（誤読しやすい語の読み）が指定されているとき、システムはその読みを合成に反映すること
3. YAML にポーズ秒数が指定されているとき、システムは指定位置に指定長の無音を挿入すること

## Requirement 3: 執筆時の素材候補収集（Claude 側ワークフロー）

**User Story:** As a 動画制作者, I want 台本執筆時に Claude が素材候補の収集とライセンスの下調べまで済ませておきたい, so that 実行時には承認するだけで済み、権利確認の漏れも防げる.

### Acceptance Criteria

1. 台本執筆時、執筆ワークフローはシーンごとに素材ソース（ストック素材は Pixabay / Pexels、実在の人物・事物は Wikimedia Commons 主、必要に応じて汎用画像検索）を検索し、画像・動画クリップの候補 URL を 2〜4 件、ライセンス情報とともに YAML に記録すること
2. ストック素材を候補にするとき、執筆ワークフローは商用利用可・クレジット表記不要のソースに限定すること
3. Wikimedia Commons の候補を記録するとき、執筆ワークフローは PD / CC の別と、CC の場合の出典表記文字列を YAML に記録すること
4. ライセンス不明の画像（汎用検索由来）を候補にするとき、執筆ワークフローは出典 URL を必ず記録し、候補に「権利要確認」の印を付けること
5. 存命人物の画像を候補にするとき、執筆ワークフローは肖像権・パブリシティ権の注意を候補に付記すること
6. BGM について、執筆ワークフローは商用利用可のフリー音源から候補曲を検索し、ライセンス確認結果と URL を提示すること（ダウンロードと配置はユーザーが行う）

## Requirement 4: 素材候補ギャラリー（人の承認）

**User Story:** As a 動画制作者, I want レンダリング前にシーンごとの素材候補をギャラリーで確認して選びたい, so that 審美判断と権利判断を自分で下しつつ、選択以外の作業はすべて自動化できる.

### Acceptance Criteria

1. レンダリング前に、システムはシーンごとの候補素材（画像・動画クリップ。執筆時に収集された候補セット）を一覧表示するローカル Web UI（候補ギャラリー）を提供すること
2. ギャラリー表示のとき、システムは各候補にライセンスバッジ（PD / CC-BY / 商用可 / 権利要確認）を表示すること
3. ユーザーが候補を選択したとき、システムはその画像をダウンロードして中間素材フォルダに保存すること（リンク切れ対策）
4. ユーザーが「候補に合うものがない」と判断したとき、システムはギャラリー上での再検索（クエリ編集含む）を提供すること
5. ユーザーが素材を選択しなかったシーンについて、システムはテロップ＋背景のみの画面構成でレンダリングすること
6. 権利要確認の画像が採用されたとき、システムは出典 URL の記録と出典テロップの生成を必須とすること（引用要件への対応）
7. システムはユーザーの明示的な操作なしに画像生成 API を呼び出さないこと（課金の承認制）
8. 動画クリップの候補について、システムはギャラリー上でプレビュー再生を提供すること

## Requirement 5: 生成 AI による画像フォールバック

**User Story:** As a 動画制作者, I want 素材サイトに理想的な画像がないときやスタイルを統一したいときに生成 AI で画像を作りたい, so that どのシーンにも過不足ないビジュアルを用意できる.

### Acceptance Criteria

1. ユーザーがギャラリーで「生成 AI で作る」を選択したとき、システムはクラウドの画像生成 API（商用利用可のもの）でシーン用画像を生成すること
2. 画像を生成するとき、システムは全シーン共通のスタイル定義（YAML に 1 箇所）とシーン別の内容プロンプトを連結してプロンプトを構成すること（スタイル統一）
3. 生成 AI の対象は静止画のみとすること（動画生成は将来拡張。ストック動画素材の利用は Requirement 4・6 で扱い、本要件の制限対象ではない）

## Requirement 6: 映像レンダリング

**User Story:** As a 動画制作者, I want テロップ・素材・出典表示を配置した映像をシーン音声と同期して自動合成したい, so that 編集ソフトを開かずに完成動画が得られる.

### Acceptance Criteria

1. レンダリングを実行したとき、システムはシーンごとに「背景＋シーン見出し＋テロップ＋採用素材」を音声の長さに同期して合成すること
2. 静止画素材を表示するとき、システムは自動ズーム・パン（Ken Burns 効果）で動きを付与すること
3. 出典情報が記録された素材を表示するとき、システムは出典テロップを同一シーン内に表示すること
4. ナレーション本文から、システムは字幕（SRT）を生成すること
5. 動画素材を表示するとき、システムはシーンの尺に合わせてトリムまたはループし、クリップ自体の音声をミュートして合成すること

## Requirement 7: BGM の自動ミキシング

**User Story:** As a 動画制作者, I want 指定した BGM のループ・音量調整を自動でやってほしい, so that 音のバランス調整のために編集ソフトへ戻らずに済む.

### Acceptance Criteria

1. YAML に BGM ファイルが指定されているとき、システムは動画の尺に合わせて BGM をループ再生させること
2. BGM をミキシングするとき、システムは全体のラウドネスを YouTube 基準（-14 LUFS）に正規化すること
3. ナレーションの再生中、システムは BGM の音量を自動的に下げること（ダッキング）
4. BGM の指定がない場合、システムはナレーションのみで音声トラックを構成すること

## Requirement 8: 出力（完成動画＋中間素材）

**User Story:** As a 動画制作者, I want 完成 MP4 と一緒に中間素材一式を構造化して残してほしい, so that 直したいときだけ AviUtl 等の編集ソフトで素材から組み直せる.

### Acceptance Criteria

1. レンダリング完了時、システムは完成 MP4 を出力すること
2. レンダリング完了時、システムはシーン別 WAV・字幕（SRT）・採用素材（画像・動画）・テロップ素材・タイムライン情報（各シーンの開始/終了秒）を構造化されたフォルダに保存すること
3. 中間素材は汎用形式（WAV / PNG / SRT / テキスト）で保存し、特定の編集ソフトに依存しないこと

## Requirement 9: 実行環境

**User Story:** As a 動画制作者, I want ツールを自分の PC だけで完結させたい, so that サーバ費用や運用の手間なしに使い続けられる.

### Acceptance Criteria

1. システムはローカル環境（CLI ＋ ローカル Web UI）で動作し、クラウドへのデプロイを必要としないこと
2. 外部ネットワーク通信は、素材検索 API・画像ダウンロード・画像生成 API の呼び出しに限定すること

## Open Questions

- VOICEVOX の話者選定と、規約上必要なクレジット表記（「VOICEVOX:話者名」）の挿入方法（エンドクレジット自動挿入を想定）
- 解像度・アスペクト比（1080p / 16:9 を既定と仮置き。ショート動画対応は未検討）
- 技術スタック（言語・フレームワーク）の選定
- ツール本体のリポジトリ配置（新規リポジトリ想定。本スペックの移設タイミング含む）
- 画像生成 API のプロバイダ選定（商用利用条件の確認込み）
- 将来拡張（今回は対象外）: 完全自動モード／全自動ドラフト→部分差し替え、動画生成 API、AviUtl .exo 出力、クラウドレンダリング
