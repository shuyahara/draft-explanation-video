# 対話劇台本（めたん×ずんだもん）の書き方

紙芝居版（対話劇）の台本で、ナレーション台本を二人の会話に組み替えるときの規約。
出典は 2026-09-04 のユーザー直接編集（`scripts/20260904-dopagaki-kamishibai`、コミット
6f217f0・093fd5b・84ef046）と、同日の論点指摘 2 件。正本は CLAUDE.md、本書は詳細。

## 1. ナレーション由来の癖を残さない

ユーザーが最も多く直したのは「ナレーションの文をそのまま話者に割り振った」箇所。

- **体言止め・名詞止めは会話では不自然**。「2分半が、47秒。」→「2分半が、47秒に！？」。
  「関連は、ある。因果の向きは、決められない。」→「関連は、ある。でも、因果の向きは、
  決められないのよ。」のように、接続詞と語尾で文をつなぐ。
- **めたんの言い切りは語尾で受ける**。「正しくない。」→「正しくないのよ。」、「平均47秒。」→
  「平均47秒になっているのよ。」、「そう設計されているから。」→「それはそう設計されている
  からなのよ。」。断定を減らし、相手に話している感じを出す。
- **決め文もキャラの言葉にする**。ナレーション向きの対句（「弱くなったのは、あなたじゃない。
  強くなったのは、相手のほう」）は、相手の名前を入れた話し言葉（「ずんだもんの脳が弱くなったん
  じゃないのよ。相手の方が強くなったのよ」）に。「〜画面なのよ」→「〜装置なのよ」のように
  比喩も口語で締まる語を選ぶ。元の対句はタイトル・概要欄に残せばよい。
- **通説・引用は「」で囲み、自分の言葉と区別する**（「『ショート動画は刺激が強い。…出る』。
  そういう筋書きよ」）。ツール制約: 句点は閉じ括弧の外（`」。`）。`。」` だと閉じ括弧だけの
  字幕キューが出る。

## 2. 聞き手（ずんだもん）の反応

- **一人称は「僕」**。自分を「ずんだもん」と呼ばない（呼びかけはめたんが行う）。
- **数字・事実の復唱には感情語を足す**。「9万8千人。」→「9万8千人！すごいのだ。」、
  「ひどいのだ」→「ひどい話なのだ」。名詞の復唱だけの相づちは禁止（CLAUDE.md の規約を強化）。
- **問い返しで次の説明を引き出す**。「段差を、戻す。」→「段差を、戻す。どういうことなのだ？」、
  「また落ちたのだ？ 今度は何が犯人にされたのだ？」。説明役が自分で話題を継がない。
- **当事者としての言い換え**は残す（「溺れてるんじゃなくて、空回りしてるだけなのだ」）。
- 章末の問いはずんだもんが言う（既存規約）。

## 3. 説明役（めたん）の性格付け

- 役割宣言で章を開いてよい（「〜について解説してあげるわ」）。少し硬い語彙（「紐解く」）も
  お嬢様口調として許容。
- 皮肉・余裕は `smug`、共感は `smile`、引き締めは `serious`、指差し説明は `explain`/`point` と
  表情を使い分け、同じ表情を 3 行以上続けない。改稿したら表情タグを必ず見直す（語尾や感情語が
  変わると表情も変わる）。

## 4. 導入は短く、細部は削る

- 冒頭の具体エピソード（コメント欄で言葉を見た、親指の夜勤ギャグ）はユーザーが削除した。
  **導入は「状況→言葉→問い」を最短で**。ギャグは本論の中盤以降に置く。
- 数字は伝わる方へ寄せてよい（寝ようと思った 1 時→12 時、気づいたら 2 時→3 時。「3 時間も」）。
- 犯人の言い方は具体物で（「ポケットの中の画面」→「ずんだもんが持っているスマホ。その中の設計」）。

## 4b. 婉曲・比喩より直接表現、逸話より主題（2026-09-06 指示）

- **表現的な面白さではなく、内容的な面白さ・見やすさを追求する**。決め文・章タイトル・図解キャプションは、比喩を使わずに言い直してみて、直接版のほうが分かりやすければ直接版を採る。例: 「請求書」→「代償」、「犬は権力に吠え、冷笑は本気に吠える」→「昔のシニシズムは権力を笑い、今の冷笑は本気を笑う」、「嗤う」→「笑う／あざ笑う」（読みの事故も減る）。
- 名前のついた概念（「酸っぱい葡萄」「高く伸びた芥子」）は残してよいが、直後に直接の言い換えを添える。
- **主題でない逸話は削る**。面白い雑学（ディオゲネスの甕・ランプ・大王）でも、「後のどの結論を支えるか」で残すものを選び、支えないものは丸ごと落とす。元台本にあるからという理由で残さない。
- 読みの確認は ASR だけに頼らず、`tools/preflight.py` で `audio_query` のかなと形態素解析（fugashi）の読みを全セグメントで突合する（決定的）。ASR は閾値未満の誤読（怒り→オコリ、敵同士→カタキドウシ）を見逃す。**辞書登録は最小限に**: VOICEVOX が正しく読む語（「同じ」）を登録すると複合語（「同じ人」→オナジジン）が壊れる。登録後は必ず突合で副作用を確認する。

## 5. 論理の検証（反転の主張は「何を否定しているか」を明示する）

ユーザーが見抜いた 2 件の飛躍。台本レビューでは拾えなかった。

1. **「ドーパミンは快楽物質ではない」→「『ドーパミン中毒』という言葉はずれている」は飛躍**。
   快楽物質でなくてもドーパミンは関与している。否定できるのは「快楽に溺れた」という筋書きだけ。
   → 「半分は当たっている。違うのは筋書き」と、否定する範囲を言葉にする。
2. **「順位が回復した」→「騒ぎは的外れだった」は単一データの過大解釈**。施策が効いた可能性、
   その後の再下落（PISA 2018 15 位）、比較対象側の変動（OECD 平均の低下）を無視していた。
   → 例を使う目的（ここでは「落ちるたびに犯人が入れ替わる型」）に合わせて語り直す。

チェック手順: 各章の反転（「実は〜ではない」）ごとに「否定しているのは何か／否定していないのは
何か／その根拠は 1 つのデータか複数か」を台本の判断メモに 1 行ずつ書く。系譜・列挙に入れる例は、
他の例と**同じ型**（同じ主語・同じ被告）かを確かめる。

## 6. 運用

- ユーザーは GitHub 上で直接編集する。**編集中はオーケストレーターから同じブランチへ push しない**
  （先端が動くと GitHub 側のコミットが弾かれる）。取り込みは pull／別ブランチのマージで行い、
  push は編集完了の合図の後にまとめて行う。
- 取り込み後は `tools/kamishibai_md_to_yaml.py` → `apply_beats.py`（アンカー文字列を追従）→
  `validate` → `preflight`（読み・長いキュー・板だけの区間・要確認文字等の一括チェック。
  `tools/review/README.md`） → 表情タグの見直し → レビュー一式。
- **Codex レビューは一式すべて回す**（2026-09-05 ユーザー指示。セリフレビューだけで試写に出さない）。
  台本段階: `review_script.py`（7 観点）→ `review_holistic.py`（総合）→ `review_dialogue.py`（セリフ）→
  `review_transitions.py`（章のつなぎ）→ `review_pauses.py`（間。YAML 生成後）。レンダ後:
  `review_video.py`（映像）＋ `review_reading.py`（ASR 読み）。各レビューの採否と根拠を Issue に残す。
  順序は `tools/review/README.md`、コマンドは `/review`。
- **末尾の挨拶は本編に書かない**（2026-09-05 決定）。「ご視聴ありがとうございました／高評価・チャンネル登録／コメントで意見を」は、本編とは別の見た目で作った 15 秒の独立クリップ（`assets-kamishibai/endcard/endcard.mp4`、生成は `tools/endcard/make_endcard.py`）を、レンダ時に `--end-card` で全動画の末尾に結合する。本編はめたんの決め文で閉じ、アウトロのフェードのあとにクリップが続く。
- **図解は「見せたい図のイメージ」を先に書く**（CLAUDE.md 図解の最上位規則）。対話台本では、実験の紹介は「誰に→何をした→結果（数字）」の格子、二群の違いは左右 2 列、用語は言葉＋ピクトグラムを `sketch` で組む。黒板だけの区間が 30 秒を超えたら、写真か「言葉＋ピクトグラム」で埋める（validate の情報行で確認）。
- **テロップだけの板は 10 秒以内**（2026-09-06 ユーザー提案）。上にテロップが出ているだけの黒板が 10 秒を超える場合は、写真にテロップを重ねる（image ビートの telop）か、言葉＋ピクトグラムの sketch にする。板だけでよいのは、決め文の余韻（2〜3 秒）と章カード直後の数秒だけ。validate の情報行で `board` の推定尺を確認する。
- **1 キュー（。で切れる 1 文）は 50 字以内**。紙芝居の字幕は 2 行までで、超えた分は末尾が切り落とされる（v8 で「勝ち負けの駆け引きとして報じる」の 92 字の文が見切れた）。長い研究紹介は「〜の実験よ。」で一度切ってから内容を言う。YAML 生成後に 52 字以上のキューを機械的に列挙して確認する。
- **公開タイトルの末尾に必ず `【ずんだもん&めたん|ゆっくり解説】` を付ける**（2026-09-07 ユーザー指示。
  検索でずんだもん系・ゆっくり解説系の動画として引っかかるようにするため）。形式は
  `本題｜副題【ずんだもん&めたん|ゆっくり解説】`。YouTube のタイトル上限 100 字に収める（接尾語は 18 字なので
  本題＋副題は 80 字以内）。一覧で切れる位置（30 字前後）より前に本題の要点が来るよう、副題は後ろに置く。
  アップロード時の `--title`、`publish/*/upload-record.md`、台本ヘッダの「YouTube タイトル」に同じ文字列を書く。
  ナレーション版（社会を科学する雑学）のタイトルには付けない。
- **用語・要点は「言葉＝説明文」の黒板ビートで見せる**（2026-09-07 ユーザー指示。ルッキズム版の試写で
  「写真と台本の関連が薄い箇所が散見される」と指摘）。用語の定義（「ルッキズム」「ハロー効果」「美の経済的
  プレミアム」など）、よくある答えの却下（「時代が変わったから＝何も説明していない」）、研究と推論の区切り、
  この動画で確かめることの予告は、関連の薄い写真で埋めず `board` ビートに複数行の `telop` を書く。
  **板にするのは、主題の定義・鍵になる用語・覚えてほしい要点・論の区切りだけ**（2026-09-07 試写 3 回目のユーザー指摘:
  「時代が変わったから＝何も説明していない」のような主題に関わらない却下の一言や、つなぎの問い直しは板にせず写真を出す）。
  **板の書き方の規則**（2026-09-07 試写 4 回目のユーザー指摘から一般化）:
  ① 見出しは**言葉そのもの**（用語・主張の一文）にする。「覚えておくこと」「まとめ」「ポイント」「結論」のような
  メタ語を見出しにしない（例: ×「覚えておくこと／美しい人は中身も良い」→ ○「『美しい人は、中身もきっと良い』／＝顔を見ただけで、無意識に結びつけてしまう」）。
  ② 要素が 2 つ以上あるときは **①②③ の番号付き箇条書き**にする（読点でつないだ一文にしない）。
  ③ **順序・因果・対比（A→B→C、A と B の比較）は板の文字ではなく図解**（`sketch` の格子＋矢印、または `narrative`）で見せる。
  板に「→」を 2 つ以上書きたくなったら図解の合図。
  ④ 板に載せる語はナレーションの言い回しをそのまま短くしたものに限る（板だけの新しい主張を足さない）
  （1 行目＝言葉、2 行目以降＝説明。各行 30 字以内・4 行以内。script-to-video の board 複数行対応）。
  文言はナレーションの言い回しをそのまま短くしたものにする（ナレーションにない主張を足さない）。
  複数行ボードは 20 秒まで許容（preflight `BOARD_MULTILINE_MAX_SECONDS`）。写真を使うのは、ナレーションが
  具体的な場面・物・人を述べている箇所だけにし、「別カットに替えて」だけの理由で同カテゴリを 3 枚以上
  使い回さない。
- **Codex レビューでは拾えないもの**: 冒頭の例が論の前提と合っているか（例: 冷笑の対象が「本気の人」
  であるべきところで別種の例を選んでいないか）、反転の否定範囲（§5）。これらはオーケストレーターが
  台本を書き終えた時点で自分で点検し、判断メモに残す（2026-09-05 の冷笑版 S1 の例の差し替えが実例）。
