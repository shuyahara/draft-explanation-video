### 素材候補収集ワークフロー

台本執筆時に、シーンごとの候補素材（画像・動画）と BGM 候補を調査し、YAML に記録する。
最終選択（実際に使う素材の確定）はレンダリング前の候補ギャラリーで人が行うため、ここでの役割は
「候補を集め、ライセンスを確認して記録する」こと。

**説明イラスト（生成AI）は次の順で検討する**（対象: シーン主視覚・カットアウェイ・
背景付き図解の背景のいずれも同じ手順）。

1. `visual_intent` を書く（このシーンを何の絵で見せたいか、日本語1〜2文）。
2. その情景の `gen_prompt` を**必ず起草する**（英語1〜2文。`video.style` と連結して使われる。
   **連結順は `gen_prompt` が先・`video.style` が後**——様式強制句を先頭に置くと主題への追従が
   弱くなることが実測されたため R19.6 で反転した。様式語を `gen_prompt` 側に重複して書く必要は
   ない）。
   **型は2つ使い分ける**。1つは**情景型**——「人物主語＋小道具＋一瞬のポーズ」
   （例: "a researcher pausing mid-sentence while pointing at two photographs on a table"）。
   抽象語だけの表現は避け、「誰が・何をしている場面か」を具体的に描写する。もう1つは
   **擬物化静物型**——抽象概念を、その構造を体現する「物」のメタファーで、シックな照明の静物として
   描く型（例: "an old brass balance scale on a dark desk, one pan slightly lower, warm lamplight"
   ＝比較・不均衡）。論証の主張そのものを画で支えたい場面（従来は無地図解に頼っていた箇所の一部）
   で使う。判断基準は、場面・人物の空気感を見せたい→情景型、概念の構造そのものを見せたい→
   擬物化静物型。

   **婉曲に寄せすぎない（2026-08-25 試写FB・次回作からの宿題）**: 対立・議論・関係そのものが
   主題の場面では、静物メタファーへの言い換えを既定にせず、主題を直接描く情景（例: 夜の路上で
   向き合い言い争う男女のシルエット）をまず検討する。メタファーに寄せるのは、直接描写が
   扇情的・ステレオタイプ的になりそうな場合や、概念の構造を見せたい場合に限る。

   擬物化静物型の汎用メタファー辞書（型の例。これ以外のメタファーを考えても構わない）:

   | 主張の型 | メタファー例 |
   |---|---|
   | 比較・不均衡 | 天秤／高さの違う積み木 |
   | 蓄積・増加 | 積み上がる硬貨・書類の山 |
   | 比率・多数 | 並んだ駒・椅子の群れ |
   | 選別・淘汰 | ふるい／開く扉と閉じる扉 |
   | 連鎖・波及 | ドミノ／水面の波紋 |
   | 対立・拮抗 | 綱引きのロープ／向き合う駒 |
   | 時間・経過 | 砂時計／伸びる影 |
   | 隠れた構造 | 氷山／水面下 |

   偽文字対策（下記）・before/after 不可（下記）・顔クローズアップ回避・検品3観点・再生成2回まで
   （後述「生成した説明イラストは採用前に検品する」）は型を問わず共通のルールとして擬物化静物型
   にもそのまま適用する。

   `video.style` の推奨文言（全編共通で1箇所、シネマティック様式）は
   `docs/schema.md` の `video.style` 節が正。用途別（主視覚／カットアウェイ／図解背景）の
   書き分けは script-to-video の `docs/design-rhythm-and-illustration.md` §6.3 を参照。
   **文字物（書類・書籍・看板・画面など）を描く場合は、読めない／白紙であることを明示する句を
   必ず添える**（偽文字対策。生成AIは文字らしき模様を描くが、読める文字列にはならないため）。
   例: 紙・書類は `blank paper with no writing` / `the form blurred and unreadable`、本・学術誌は
   `pages out of focus with no readable print`、看板・画面は `no text, no lettering`。
   この句が欠けていると疑われる `gen_prompt` は `validate` が警告する。詳細は `docs/schema.md`
   の `gen_prompt` 節・`docs/design-beat-rendering.md` §9.4 を参照。
   **before/after・二者比較・時系列を含む情景は生成AIに投げない**（1枚の静止画に複数時点・
   複数状態は描き分けられないため）。`diagram`（`comparison` 型。ビート運用では `narrative`
   型で言い換えられないか先に検討する）に置き換えるか、単一被写体の一場面に還元してから
   `gen_prompt` を書く。**ビート運用では、時系列（before/after）は `image` ビートを2つに分けて
   時間軸で見せる方法もある**（同一シーンに複数の `image` ビートを置けるため）。還元先は
   顔のクローズアップではなく小道具・UI操作の場面を選ぶ（顔のクローズアップは写実調へ
   様式崩れしやすいことを型検証で確認済み。`../references/20260819-genprompt-type-validation.md`
   参照）。
3. ストック素材で代替できるか判断する。一般名詞的な情景（街の雑踏、スマートフォン操作、
   統計オフィスなど）や、実写であることに意味がある画（報道写真的なもの）は
   **代替できるならストックを優先**する。代替できなければ `gen_prompt` を第一候補のまま残す
   （候補ギャラリーでの明示操作・課金承認制は変わらない）。

**数の見せ方の使い分け**

同じ「数」を見せたい場面でも、正確さが要るか印象でよいかで手段を変える。

| 見せたいもの | 手段 | 注意 |
|---|---|---|
| 正確な数値（推移・大小の比較） | `diagram` の `chart` | 裏取り済み数値のみ・動画1本1箇所まで（既存規則。上記「型の選び方」参照） |
| 規模感・比率の「印象」 | 擬物化静物型の `gen_prompt` | 生成AIは個数を正確に描き分けられないため、数字の正確さは絵に負わせない。ナレーションと `chart` が数字を担い、絵は「一方が多い」の印象だけを担う（例:「105対100」を駒の数で正確に見せる、のような使い方はしない） |
| 選別・一部が選ばれる | `narrative` の `row` | 既存（上記「`narrative` の3レイアウト」参照） |

**生成した説明イラストは採用前に検品する**（詳細は script-to-video の
`docs/design-chic-tone.md` §8 が正）。

1. `video.style` からの逸脱がないか（特に写実化。全編の画風統一が前提）。
2. ナレーション・`visual_intent` の内容と一致しているか（人数・場所・時代・持ち物のずれに注意）。
3. 人物の並置などによる意図しない含意（比較・優劣・因果の読み違え）がないか。

同一のビジュアル意図での再生成は**最大2回まで**。3回目に入りそうなときは、まず**別モチーフで
`gen_prompt` を再起草**する（偽文字で落ちた場合は文字・刻印・貨幣・書面を含まないモチーフへ
差し替える。Codex 経由の生成コストは実質無料のため躊躇しない）。それでも不可のときに限り、
図解の採用テストを通過する型の図解へ切り替える（converge への機械的切替は廃止。
2026-08-25 試写FB）。

**画像生成の運用（自動が主・手動生成は例外）**

画像生成の主力は従来どおり自動（Stability、`gen_prompt` 起草→パイプライン生成）。**構図が複雑で
自動生成が2回失敗した場合や、サムネ・オープニング級の「ここぞの1〜3枚」に限り**、ChatGPT Plus
での手動生成を許可する。

1. YAML には通常どおり `visual_intent` と `gen_prompt` を書く（再現性の記録として残す）。
2. ChatGPT には「`gen_prompt` ＋ `video.style` の様式文」を渡して生成する。
3. できた画像は素材ディレクトリに該当スロット名（`scene_NN_beatM.png` など）で配置し、候補として
   採用する。
4. 検品3観点＋偽文字チェックは自動生成と同様に適用する。
5. 手動生成であることを、YAML の該当ビート近くに **YAML コメント**で明記する（コメントはスキーマ
   の対象外で `extra="forbid"` に抵触しない）。

画風統一の注意: `video.style` の文言を必ずプロンプトに含める。全編の中で1枚だけ画風が浮いたら
不採用にする。

**冒頭シーンの実写素材は静止画を選ぶ**（動画素材には Ken Burns 効果が掛からないため）。

**実物引用ビート（実写・実物画像で説明する）**

ナレーションが具体物（論文の図表・地図・統計グラフ・歴史写真等）に触れる箇所は、生成AIの雰囲気
画像ではなく**実物の画像を `image` ビートの `assets` として出す**ことを検討する（説得力が最も
強い選択肢として、`gen_prompt` より優先して検討してよい）。

- ライセンスは限定する。パブリックドメイン（`license: pd`）／CC BY 系（`license: cc-by`。
  `source_url` と `attribution` が既存規則どおり必須）／**日本の政府統計・官公庁サイト**
  （政府標準利用規約は CC BY 互換のため `license: cc-by` として記録し、`attribution` に
  出典を書く）の3種に限る。汎用画像検索由来（`license: unknown`）は引用用途では使わない
  （権利未確認の画像で「これが実物です」と示すのは事実性のリスクが高いため）。
- 出典は必ず `telop` で表示する（既存の出典表示規則と同じ）。`source_url`・`attribution` の
  記録は既存の `assets` 規則どおり。
- 論文図表は原著の Figure をそのまま使える場合のみ使う（改変しない）。使えない場合は数値を
  `chart` に起こす（既存路線。上記「数の見せ方の使い分け」参照）。

ストックの候補を集める場合は、次の手順でライセンスを確認して記録する。

1. シーンごとに素材候補を **2〜4件**、ライセンス情報とともに YAML の `assets` に記録する。
2. ストック素材は **Pixabay / Pexels**（商用利用可・クレジット表記不要）に限定して探す
   （YAML では `license: commercial-ok`）。
3. Wikimedia Commons の候補は PD か CC の別を確認する。CC の場合は出典表記文字列を
   `attribution` に記録する（`license: cc-by` の場合、`source_url` と `attribution` が必須）。
4. ライセンス不明（汎用画像検索由来）の候補は `license: unknown` とし、`source_url` を
   必ず記録する（権利要確認マーク）。
5. 存命人物が写る候補には、肖像権・パブリシティ権の注意を `note` に付記する。
6. BGM は商用利用可のフリー音源（例: DOVA-SYNDROME）から候補曲を検索し、ライセンス確認結果と
   URL を提示する。ダウンロード・配置はユーザーが行うため、YAML の `video.bgm` には
   （配置予定の）ファイルパスのみ記録する。BGM が確定したら、クレジット表記文字列を
   `video.bgm_credit` に記録する（`description.txt` に自動転記される。省略時はファイル名
   ベースのフォールバック表記になる）。
- `search_query`（素材検索クエリ）は **英語** で書く（Pixabay / Pexels / Commons の検索に
  渡すため）。
