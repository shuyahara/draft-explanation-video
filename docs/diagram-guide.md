### 図解スクリプト（`diagram`）

抽象概念・因果関係・比較・手順・データは、実写素材ではなく **図解**（アイコン・ラベル・矢印・
棒/折れ線をモーション付きで組み上げる説明背景）で表現できる。書くのは「型」「要素の並び」
「id・ラベル」「どのセグメントで出現するか（`at`）」だけで、位置・サイズ・色・アニメーションの
数値は一切書かない（レイアウトと動きはツール側が決定的に計算する）。仕様の詳細（型ごとの
フィールド・上限・バリデーション）は `docs/schema.md` の `diagram` 節が正。ここでは執筆判断の
要点だけをまとめる。

**ビジュアル意図を最初に書く**（Requirement 16.1）

シーンごとに、図解・検索クエリ・生成プロンプトを決める**前に**「どんな絵で見せたいか」を
1〜2文で決める。先に手段（図解 or 素材）を選んでから理由を後付けすると、「図解のための図解」
や「画面が寂しいだけのシーン」になりやすいため、必ず意図が先。

- 決めたビジュアル意図は、台本 Markdown の「ビジュアル」欄と、シーン YAML の `visual_intent`
  の両方に同じ内容で書く（`visual_intent` はレンダリングには使わず、候補ギャラリー表示にのみ
  使う短い自由文。仕様は `docs/schema.md` の `visual_intent` 節）。
- `diagram` の型・`search_query`・`gen_prompt` は、このビジュアル意図から導く。

**画面構成は3種類**（Requirement 16.2。専用フィールドではなく `diagram` と `assets` の有無の
組み合わせで表す。旧仕様の「図解 or 実写の択一」を、背景付き図解を加えて発展させたもの）

| ビジュアル意図の傾向 | 画面構成 | YAMLの書き方 |
|---|---|---|
| 情景描写・具体的な人／物／場所・フック（つかみ）・エピソード | 全画面実写 | `assets` のみ |
| 論証・手順・比較・データを図で見せたい。情景の支えは不要（画面が持つ） | 図解のみ（無地下地） | `diagram` のみ |
| 論証・手順・比較・データが軸だが、画面が寂しい／情景の空気感も一緒に見せたい | **背景付き図解** | `diagram` ＋ `assets` を併記（排他ではない。素材にぼかし＋暗色スクリムをかけて図解を重ねる） |

- **抽象概念のシーンでも「情景の支えが欲しい」と判断したら背景付き図解を選ぶ**
  （例: 定義や構造を示す図解の背後に、街の雑踏など情景の空気感を敷く）。
- 迷ったら無地下地から検討する。結論・まとめなど**引き締めたい場面は無地下地のままでよい**
  （背景を足すこと自体を目的化しない）。
- **説明イラストは「説明イラスト第一」で考える**（詳細は後述「素材候補収集ワークフロー」）。
  「実験で参加者が写真を見比べている」のような説明的な情景は、ストック検索ではまず出てこない
  ため、`gen_prompt` を先に起草してからストックで代替できるか判断する。一般名詞的な情景
  （街の雑踏、スマートフォン操作など）や、実写であることに意味がある画は引き続きストックを
  優先する。ギャラリーでの明示操作・課金承認制は変わらない。
- **非ビート運用（v5互換）**では、論証型の台本は図解（無地下地／背景付き問わず）が主体になるが、
  情景の情報量は実写に残す。目安として図解シーンは全体の3〜5割（全部を図解にすると単調になる）。
- **ビート運用**では、この比率はシーン単位ではなく**ビート単位**で考える。R19 のベンチマークが
  示す画面様式は「生成AIの一枚絵（`image` ビート）を主役に据え、列挙・因果・比較など構造的な
  主張の場面だけ `diagram` ビートに切り替える」。図解ビートを連続させすぎない（旧来の「ピルの
  羅列」に戻ってしまうため）。全体としての目安は変わらず3〜5割程度が図解が占める形。

**型の選び方**

| 台本での役割 | 型 | 目安 |
|---|---|---|
| 状態が変わることが主張を運ぶ（1つの特徴が波及／論拠が結論へ収束／選別が起きる） | `narrative` | `layout: radiate`/`converge`/`row`。**ビート運用（`beats`）での第一候補** |
| 主張を積み上げる／原因から結果へ／前提から帰結へ | `buildup` | 3〜12要素・5行まで |
| 実験の手順・時間順に進む処理・ステップの説明 | `flow` | 3〜6ステップ |
| 「AとBはどう違うか」「短期と長期」「従来と提案」 | `comparison` | 対比5組まで |
| 裏取り済みの数値を見せる（推移・大小の比較） | `chart` | barは1系列3〜8点／lineは3系列まで・各3〜10点 |

迷ったら、ビート運用（`beats`）では `narrative`、非ビート運用（v5互換）では `buildup`。
**ビート運用では旧来のピル型（`buildup`/`flow`/`comparison`）は `chart` を除いて非推奨**
（存置はするが新規シーンの第一候補にはしない。`validate` が `beats` 内のピル型使用を情報行で
知らせる。`chart` は裏取り済み数値の提示に引き続き必須なので対象外）。
型が合わない図を無理に押し込むより、シーンを分けて2つの図解にする方がよい。

**`narrative` の4レイアウト**（ピルを使わず、ピクトグラム・下線・極太タイポで状態変化を見せる）

| layout | 場面 | 件数 |
|---|---|---|
| `radiate` | 中心の1特徴から他の評価へ広がる（例: 外見の魅力→温かい・社交的・能力が高い…と波及） | items 3〜6件 |
| `converge` | 複数の論拠が1つの結論へ収束する | items 2〜4件 |
| `row` | 同型の要素が並び、一部だけ選ばれる／沈む（選別） | count 4〜10 |
| `chain` | 因果・時系列の一本鎖。層（バンド）を縦に積み、下向き矢印で流れを見せる（例: 少数の発信者→呼応→荒らしの3層構造。ナレーションが「層」「段階」を語る場面の第一候補） | items 2〜5件 |

ラベルは12文字以内（`result` は16文字・`caption` は20文字）。座標・色・アニメーションは書けない
（既存型と同じ制約）。ナレーション中の列挙を語順に合わせて出したいときは、要素に `after`
（そのキュー本文にちょうど1回だけ現れる部分文字列）を添える。文字数比で按分した時刻に出現する
（省略時はキューの開始時刻）。（仕様の正は script-to-video/docs/schema.md）

**書き方の手順**

1. 先にナレーションを書く。次に「どの文で何が新しく登場するか」を決める。
2. その切れ目でナレーションのセグメントを分ける。図解の出現粒度はセグメント粒度で決まる。
   **文の途中では分けない**。
3. 型を選ぶ（上表）。
4. 図解の最終形（全要素が出た状態）を書く。
5. 各要素に `at: <セグメント番号>`（1始まり）を付ける（`chart` は系列単位）。
6. 章が変わるところで `key_color` を変える（任意）。**`key_color` は明度（L）のみが読まれ、
   5段階（tone -2〜+2）に量子化されて下地の明度差として反映される**（色相・彩度は読まれない。
   全編の色相・彩度はツール側で固定）。章の識別は章カード（`chapter_title`）が本線で、
   `key_color` の明度差はあくまで補助。同じ章のシーンには同じ値を書く。（仕様の正は
   script-to-video/docs/schema.md）

**図解の採用テストと反復抑制（2026-08-25 試写FB・最上位規則）**

- **採用テスト**: 図解を書く前に「見て初めて増える情報があるか」を判定する。通過条件は
  次のいずれか: ①裏取り済み数値2点以上を同時に視界に置く必要がある ②空間・構造の配置が
  研究知見そのものである ③比率・選別を視覚化する。ラベルがナレーションの言い換え・写し
  だけの図解は書かない。通過した図解は、担っている構造情報（順序・比率・方向・層・対比）を
  cut_reason に一言で明記する（例「比率を担う」「因果の順序を担う」）。不通過の場面は
  「一枚絵（既出素材の再提示可）＋テロップ」で見せる。
- **converge の使用条件**: items が互いに独立な論拠であり、result がそれらから導かれる
  推論であるときだけ使う。既出内容の文字再掲・時系列の転回（→image ビート分割）・並列の
  例示（→一枚絵＋テロップ）・比率の主張（→row）には使わない。result にナレーションの
  写しを書かない。
- **同型上限**: 同一の図解型・layout は動画1本につき2回まで。前後する図解ビート（間に
  image を挟んでも図解列として隣接）に同じ layout を使わない。意図的な対句だけ例外とし、
  cut_reason にその旨を書く。図解の総数目安は10分あたり5〜6箇所（validate の同型反復
  リント〔R25-2〕が警告する）。
- **背景付きを既定に反転**: ビート運用の diagram ビート・typo ビートは背景付き（diagram は
  slot/assets/gen_prompt 併記。typo は新規台本では不使用〔上記「決め文と結びの規則」〕だが、
  使う場合は slot 指定または直前 image 素材の自動流用〔R25-1〕）を既定とする。無地は「引き締め」の意図がある場合の例外とし、cut_reason に理由を書く。
  無地ビートを2連続させない。chart は従来どおり無地可（戦略的な疎密を残す）。
- **単発数値はビート telop が担う**: chart に値しない一発の数値（+2.3%、46% 等）は図解
  ラベルではなくそのビートの telop に載せる。「既出画像の再提示（zoom_in）＋telop」を
  図解と並ぶ第一候補としてよい。telop に載せる数字は chart と同じく裏取り済みのみ。
  比率を粒の点灯で見せる場合、点灯比は語られる数値に一致させる（乖離±1%以内）。
- **文言の近接重複禁止**: 図解ラベル・telop・emphasis の同一またはほぼ同一の文字列を
  約10秒以内に2度画面に出さない。決め文は typo に譲り、図解側は別の語に言い換える。

**守るルール（チェックリスト）**

- [ ] ラベルは12文字以内（体言止め・キーワード。文を入れない。ナレーションの言い換えであって写しではない）。
- [ ] 座標・サイズ・色・アニメーションは一切書かない。書けるのは `key_color`（`#RRGGBB`）だけで、それも明度（L）しか使われない（色相・彩度・下地色はツールが固定する）。
- [ ] `buildup`: 1行4要素まで・5行まで・合計12要素まで・矢印12本まで。矢印は隣接する行の間で引く。
- [ ] `flow`: 3〜6ステップ。矢印は自動で引かれるので書かない。分岐は表現できない（必要なら `buildup` へ）。
- [ ] `comparison`: 対比5組まで。`accent`（`left`/`right`/`both`）は本当に言いたい対比点だけに付ける（全部に付けると強調が消える）。
- [ ] `chart`: 数値は必ず裏取り済みのものだけ（推計値・概算は使わない）。`source` に出典を書く（画面下に小さく焼き込まれる。音声では読まない）。**動画1本につき `chart` は1箇所まで**（多用するとデータ動画のように単調になる）。
- [ ] `narrative`: `radiate` items 3〜6件／`converge` items 2〜4件／`row` count 4〜10／`chain` items 2〜5件。ラベル12文字以内（`result`16文字・`caption`20文字）。`after` はそのキュー本文にちょうど1回だけ現れること（0回・2回以上はエラー）。
- [ ] 強調（`accent: true`）は1シーンに1箇所を目安に。結論・キーワード・対比点に使う。
- [ ] アイコン名は Material Symbols（https://fonts.google.com/icons ）の名前をスネークケースでそのまま書く。迷ったら `validate` が候補を出すので、まず書いて検証する。
- [ ] 図解はナレーションを読んでいれば理解できる補助であること。図を見ないと分からない情報を図だけに置かない。

**セグメント分割のコスト**: TTS はセグメントごとに個別合成して連結するため、分割点にはエンジン
既定の前後無音が入る。文の切れ目で分ける限り自然な間になるが、意味のない細切れ分割はテンポを
悪くする。図解の出現が必要な箇所だけ分ける。
