### ビート運用（`beats[]`。v6 以降の標準）

v6 以降、シーンの映像トラックは `beats[]`（ビート＝画面が変わってから次に変わるまでの区間）で
構成する。旧来の「1シーン＝1枚の主視覚＋1つの図解」という粒度をやめ、シーン内で `image`
（一枚絵）・`diagram`（図解）・`typo`（強調カット）・`chapter`（章カード）の列として画面を
設計する。仕様は `docs/schema.md` の `beats[]` 節、設計判断の背景は
`docs/design-beat-rendering.md` が正（本節は執筆判断の要点だけをまとめる）。

- **v5（凍結中の旧台本）は無改変**。`beats` を書かないシーンは従来どおりのレンダリング経路
  （実写／図解の単一主視覚）で動く。移行の強制はない。
- `beats` を使うシーンでは、シーン直下の `assets` / `gen_prompt` / `search_query` / `diagram` /
  `diagrams` / `cutaways` は書けない（エラー）。主視覚・図解・インサートはすべて対応する
  ビートが持つ（一部区間だけに被せるインサートを表現したい場合は `image` ビートを分ける）。
  `telop` / `key_color` / `chapter_title` / `chapter_bgm` / `emphasis` / `readings` /
  `visual_intent`（シーン直下）は挙動不変（音声・章・色の正本のまま）。（仕様の正は
  script-to-video/docs/schema.md）

**ビート境界は「意味の節目」に置く**

- 字幕キューの機械的な分割（1文＝1カット）ではなく、**話題・主張・場面が変わるところ**で切る。
  同じ話題を掘り下げている間は1枚を保持する。
- 一枚絵の保持は **8〜15秒を目安**にする。20秒を超えると `validate` が警告する
  （「同じ絵が長すぎます。話題の節目でもう1枚に分けるか、図解を挟んでください」）。
- **大きな転換（章の変わり目・場面転換）はセグメント境界（ポーズがある位置）に合わせる**。
  同じ段落内の細かい切り替えはキュー境界で構わない。精度が要る箇所はナレーション自体を
  `pause_after` で分ける。
- **ビート境界は字幕キュー（≒文）境界にしか置けない**。1枚の保持が10秒を超えそうな長い1文は、
  執筆段階でナレーションを2文に分けてキュー境界を作っておく（後から分割できなくなるため。
  R19 実台本検証 19.12 で判明）。
- 図解の決め要素（結論ラベル・光の輪など）の `after`（語同期）は**句の終端語に置かない**。
  `after` は「その語の終わり」の時刻なので、キュー末尾の語を指定すると要素の保持がほぼゼロに
  なる。決め要素は終端の1〜2秒手前の語に同期させる。
- 各ビートに **`cut_reason`（ここで画を切り替える理由）を必ず書く**。レンダリングには使われず
  `validate` とギャラリーが表示するだけだが、後から「転換が早すぎる」等の判断をこの欄だけで
  やり直せる。書き方は「【何が起きる場面か】なぜここで束ねる／切るか」の一言（例:「【学問的
  背景の提示】キュー1〜3は同じ『知見を紹介する』動作なので1枚で持たせる」）。

**決め文と結びの規則（2026-08-25/26 試写FB・ルール）**

- **決め文の文字カット（emphasis＋typo）は新規台本では使わない**（2026-08-26 改訂。決め文は
  直前の文章と情報が同じで、大文字表示は機械感を生むため）。決め文の演出は「画面を保持した
  まま、直後に `pause_after` 2.0〜2.5秒の無音の間を取る」だけにする（章カードの大きな表示は
  従来どおり使ってよい）。emphasis/typo の機構はツールに存置するが、新規シーンでは書かない。
- **動画の最後は象徴的な一枚絵（`image` ビート）で終え**、アウトロ（最終フレーム保持＋BGMの
  余韻）につなぐ。アウトロは `--outro-seconds 8` を標準とする（2026-08-26。既定4秒では余韻が
  短い）。
- **列挙・収束の図解だけでシーンを長く持たせない**。無地の文字列挙が続くと退屈になるため、
  列挙部は情景・直接描写の `image` ビートで見せ、図解は問い・結論の収束部だけに絞る。

**ビート種別の使い分け**

| 種別 | 用途 | 執筆メモ |
|---|---|---|
| `image` | 一枚絵。2.5Dパララックス／ズームでモーションを付ける | `motion` は**原則省略**（既定 `parallax`。方向はツールが自動割り当て）。意味がある時だけ明示する: 奥行きのある画＝`parallax`（既定）、収束・集中を見せたい＝`parallax_in`、広がり・並び・移動を見せたい＝`parallax_left`/`parallax_right`、平面的な画（壁一面・紙面・グリッド等で視差がほぼ出ない／破綻する）＝`zoom_in`/`zoom_out` |
| `diagram` | 図解。既存の `diagram` スクリプトをそのまま埋める | `narrative` が第一候補（前述）。要素の `at` は**字幕キュー番号**として解釈される（非ビート運用のセグメント番号とは異なる点に注意） |
| `typo` | 決め文の強調カット | 文言を持たない。`at` で対応する `emphasis[].at` を指すだけ（文言は `emphasis[].text` が正） |
| `chapter` | 章カード | シーンの**先頭ビートとしてのみ**許可。`chapter_title` があるとき必須（逆に無ければ先頭を `chapter` にできない） |

（仕様の正は script-to-video/docs/schema.md）

- `image`/`diagram`/`chapter` ビートの `slot`（採用素材スロット番号。ファイル名
  `scene_NN_beatM.*`）はシーン内で一意にする。
- キュー番号（字幕の文区切り）はナレーション本文の「。！？」区切りから機械的に決まるため、
  TTS を回さなくても `validate` の採番表で数えられる。執筆時はこの表を見ながら `from` を
  付け直す。（仕様の正は script-to-video/docs/schema.md）

**注目誘導の近似パターン（ポインティングの代替）**

現スキーマには丸囲み・矢印・部分ハイライトのような「ここを見て」を直接指せるフィールドは無い。
代わりに次の組み合わせで代替する。

1. `motion: zoom_in` で対象へ寄る。
2. 同じ画像を別ビートで再提示し、話題の焦点を切り替える（`cut_reason` に切り替えの意図を書く）。
3. `telop` で見てほしい要素を名指しする。

**本物のポインティングが欲しかった箇所は、該当ビートの `cut_reason` 末尾に「(要ポインティング)」
と記録**しておく（将来のツール拡張の判断材料として集める。書くだけでレンダリングには影響しない）。
